# AGENTS.md — TG Media Saver (Web K/A fork)

Context for coding agents and developers.

## What this is

A Chrome MV3 extension that saves video and audio from Telegram Web K
(`web.telegram.org/k/`) and Web A (`web.telegram.org/a/`), including chats that disable saving.
Fork of [eiler2005/tg-media-saver](https://github.com/eiler2005/tg-media-saver) (MIT), limited to
those two clients and to the extension distribution path. Not affiliated with Telegram.

## Files

```
src/content.js          # the only source of logic; edit here
extension/manifest.json # MV3, MAIN-world content script, /k/ and /a/, no permissions
extension/content.js    # generated by scripts/build.sh, do not edit
extension/icons/        # static icons
test/                   # node --test suites (unit, download engine, boot, build)
scripts/build.sh        # copies src/content.js into extension/
```

## Why the code looks like this

- **Page-context fetch.** Both clients serve media through their own Service Worker, and both
  only release bytes when the fetch runs in the page world. That is why the script is injected
  with `"world": "MAIN"` and calls `window.fetch`.
  - `/k/`: `/k/stream/<urlencoded JSON>`; the descriptor carries name, size and mime. Ranged 206.
  - `/a/`: `/a/progressive/document<id>` for playback. Rewriting `progressive` to `download`
    returns the whole file as one 200 stream — the endpoint Web A's own "Save as" uses. No file
    name in the URL, so saves fall back to `document<id>.<ext>`.
- **No permissions.** The manifest asks for none; match patterns are the only surface. Keep it
  that way. Do not add background workers, storage or broad hosts.
- **Capture by polling.** `video`/`audio` `currentSrc` is polled every 600 ms. Telegram swaps
  media without firing events we can rely on.
- **Saving.** `showDirectoryPicker` once, then `getFileHandle(name, {create:true})` per file.
  Without the File System Access API the engine falls back to an in-memory Blob.
- **Queue.** One promise chain serializes downloads so progress states do not interleave.
- **Batch panel.** Captured URLs are deduped in a `Map` and rendered as checkbox rows. A URL
  stays downloadable while the tab is open, because both clients address media by hash or
  descriptor, so items outlive the element being unloaded. `scan()` is the only code that drives
  the message list: it walks the nearest scrollable ancestor upward until history stops loading,
  then restores the offset. The list is memory-only.

## Invariants

- Edit `src/content.js`; run `bash scripts/build.sh` before testing or committing.
- Version lives in `extension/manifest.json`; mirror it in `CHANGELOG.md`.
- `test/download.test.js` uses `__setDir()` from the module exports to inject a fake
  directory. Keep that hook when refactoring `download()`.
- Plain JS, no runtime dependencies, no transpiler.
- Comments explain the non-obvious (CSP, Service Worker, page-context fetch). Do not narrate
  the code.

## Checks before committing

```bash
npm test
bash scripts/build.sh
```

Manual check: load `extension/` unpacked, open `/k/` and `/a/`, play a video in each, confirm ⬇
saves a playable file. Then open ☰, run **Scan**, and confirm the list grows and downloads land
in the granted folder.
